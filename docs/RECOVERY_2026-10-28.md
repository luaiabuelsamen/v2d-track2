# The 2026-10-28 scratchpad loss, and how the entry was rebuilt

A reboot wiped `/tmp/claude-1000/...` on 2026-10-28. That directory held every arm's run
directory, the staged reference trees, the released-dataset copy and both packed CSVs — in other
words, everything the wave-2 entry had been assembled *in*. This is what was lost, what survived,
how the entry was put back, and the proof that what came back is the same entry.

## What survived, and why

| | where | survived |
|---|---|---|
| the 30 shipping rollouts and their checkpoints | `ship_ckpts_wave2/<tag>/policy_<steps>/` | yes — home disk |
| what ships per episode, and from which arm | `results/tier2_entry_wave2.json` | yes — in git |
| 29 of 30 episodes' reference root | `/home/jetson3/projects/v2d-clean-refs/bridge_v1` | yes — home disk |
| e01's reference root | the released dataset | re-downloadable, free |
| every arm's run directory, logs, per-checkpoint rollouts | `$S/second_wave/...` | **gone** |
| the staged reference trees and the md5 manifests | `$S/sw_*` | **gone** |
| both packed CSVs and their pack records | `$S/t2_entry_wave2` | **gone** |
| **e29's selected rollout and checkpoint** | `$S/second_wave/run_B.../e29` | **gone** |

The entry record is what made recovery possible. `v2d stage-entry-wave2` had reconstructed the
per-episode provenance from `$S/sw_*/provenance.json`, which the reboot also took, so
`results/tier2_entry_wave2.json` — in git, and carrying the arm, the checkpoint digest, the
environment steps and the frame-reference root for all 30 — was the only surviving copy of the
decisions. Nothing in the rebuild re-decides anything; it all comes from that file.

## The rebuild

`v2d restage-entry` (`src/v2d/submit/restage.py`) walks the entry record and rebuilds the two trees
the kit packer reads — `rollouts/` and `frame_refs/` — from the surviving checkpoints, with the
wiped dataset path redirected to a fresh download of the released data. It **verifies rather than
assumes**: every rollout's `policy.safetensors` is re-digested and compared with the digest the
entry registered, so a file that happens to sit at the right path but is not the checkpoint that
trained the entry is a refusal, not a silent substitution. A missing episode is named and refused
by default.

The proof that the rebuild is faithful, all of it recomputed rather than asserted:

- **29/29 checkpoint digests matched** the registered ones on the first run (30/30 after e29).
- **29/29 frame counts matched** the pre-reboot record, re-measured from the reference parquets.
- Re-scoring the restaged trees reproduced the survived per-clip scores at **diff 0.00e+00** on
  e00, e01 and e09 — three clips drawn from three different reference roots.
- All 29 surviving `score.json` files matched the entry record exactly, and the arithmetic closed:
  `(0.459645 × 29 + 0.5638) / 30 = 0.4631253`, the mean the pre-reboot entry recorded.

## e29, the one episode that could not be rebuilt

e29's rollout existed only in the scratchpad, so there was nothing to verify a copy against. It
was re-run rather than reconstructed: group **A29**, arm A's own recipe (`start_curriculum`,
`orientation_reward`, `object_position` at std 0.08), seed 42, the full 349,999,104 steps,
`scene.support=false` because e29's support USDA carries no primitives, on the same bridge_v1
reference the lost rollout trained on. One box, 4.01 observed box-hours, **$2.73**.

It is a **re-roll, not a recovery**: a different rollout from the same recipe and the same
selection rule. The record says so — the new e29 row carries the lost row verbatim under
`lost_in_the_reboot`, and `results/tier2_entry_wave2.json` has a top-level `e29_rerolled` block
giving the reason, the run record and the before/after score. The re-roll came back at kit AUC
**0.6270** against the lost rollout's 0.5638, so the entry's four-clip and 30-clip means are both
*better* than before the loss, which is luck and is recorded as luck.

`brev/finish_e29.sh` is the whole sequence after it landed, in one command, so it runs the same way
every time: adopt the registered z-drop pick, restore it into the backup, rewrite the e29 row,
restage all 30 with no `--allow-missing`, pack both tracks, validate, score. It refuses a commit
that is not an ancestor of `origin/main` and a policy digest that disagrees with the run record.

## What changed because of this

- The packed entry is no longer only in the scratchpad: `/home/jetson3/projects/v2d-entry-wave2`
  holds both CSVs, both pack records and the restage record on the home disk.
- `ship_ckpts_wave2/` was already the backup that saved this. It stays.
- The entry record is the load-bearing artefact, not the run directories. It is in git, and the
  rebuild path reads it rather than the trees.
